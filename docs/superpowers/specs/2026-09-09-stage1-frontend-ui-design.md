# 阶段一前端 UI 设计：JD解析与岗位胜任力模型

> 文档状态：已整理，作为阶段一前端实现依据
> 适用范围：阶段一 JD 收集、解析、模型审阅、确认与导出
> 依赖文档：[全局交互基线设计](../../../design/00-全局交互基线设计.md)、[阶段一业务设计](../../../design/01-阶段一-JD解析与岗位胜任力模型设计.md)

## 1. 设计目标与边界

阶段一前端采用统一 AppShell：左侧历史任务导航、中部主 Agent 对话、右侧阶段一工作台。用户既可以通过对话，也可以直接操作工作台；两者写入同一业务状态并生成同一领域事件。

本文件只定义阶段一专属页面、组件、交互、状态反馈和验收映射，不重新定义全局布局、颜色、响应式、证据抽屉通用行为或 Agent 动态回答规则。阶段二测评和阶段三人才画像不在本文件实现范围内。

## 2. 页面信息架构

```text
AppShell
├─ 顶部栏：项目 / 阶段轨道 / 当前版本 / 可信度 / 用户菜单
├─ 历史任务导航：新建、历史列表、折叠/展开
├─ 主对话区：Agent、用户消息、操作卡片、证据引用、输入区
└─ 阶段一工作台
   ├─ 分析状态与进度
   ├─ 总模型
   └─ 单份 JD 模型
      ├─ JD 选择器与筛选
      ├─ 解析结果列表
      └─ 条目详情 / 证据视图
```

一级分页固定为“总模型”和“单份 JD 模型”，不得按 JD 数量动态创建页签。“待确认项”通过徽标、筛选器和任务入口呈现；“证据”通过条目详情视图呈现。

## 3. 核心组件与职责

| 组件 | 职责 | 关键状态/输入 |
|---|---|---|
| `AppShell` | 三栏布局、顶部栏、响应式工作台容器 | 当前项目、阶段、版本 |
| `HistoryNav` | 新建任务、历史任务列表、当前任务高亮 | 项目列表、项目状态 |
| `ConversationTimeline` | 渲染用户、Agent、系统事件和证据卡 | 领域事件、消息、证据引用 |
| `MaterialDialog` | 粘贴文字、上传文件、提交链接、插件材料四种入口 | 输入类型、校验错误、提交状态 |
| `OperationCard` | 展示动作、对象、结果、影响和撤销/查看入口 | `DomainEvent` |
| `StageRail` | 展示阶段位置、前置条件和完成状态 | 项目状态、模型版本 |
| `StageWorkbench` | 阶段一右栏容器和分页切换 | 分析数据、当前页 |
| `JdPicker` | 搜索、状态/子岗位/可信度筛选及移出分组 | JD 列表、筛选条件 |
| `SingleJdModel` | 展示单份 JD 的能力、资历、证书、约束和原文结构 | JD 解析结果 |
| `TotalModel` | 结论优先展示共性能力、子岗位能力和风险 | 聚合模型、冲突数 |

| `ReaddJd` | 将已移出 JD 重新加入当前模型 | JD 参与状态 |
| `FinalReview` | 确认前摘要、阻塞冲突、探索性风险和确认操作 | 草稿模型、风险 |

## 4. 页面与交互规则

### 4.1 材料添加

“添加材料”打开 `MaterialDialog`，支持粘贴文字、TXT/PDF/DOCX 文件、公开链接和浏览器插件提交。提交后立即显示 `RECEIVED` 状态和操作卡片；原文不可编辑覆盖。

### 4.2 解析进度与失败

工作台显示每份 JD 的处理步骤：接收、提取文本、清洗、抽取要求、规范化、建立模型。单份失败不阻塞其他 JD。失败视图保留来源记录，并提供针对失败原因的恢复动作；重试不得创建重复 JD。

### 4.3 总模型

总模型采用结论优先的单列列表，展示能力名称、类别、权重、要求等级、来源 JD 数、证据数、可信度和待确认状态。经验、证书和约束独立分组，不计入能力权重。点击能力、权重或“为什么”进入详情视图。

### 4.4 单份 JD 模型

通过 `JdPicker` 选择 JD，不为每份 JD 增加一级页签。列表支持标题、公司、来源和关键词搜索；空搜索显示全部；已移出 JD 单独分组且明确“不参与当前总模型”。详情视图在工作台内替换列表，不使用覆盖全应用的大弹窗。

### 4.5 证据与编辑

详情视图依次展示当前结论、原文证据、规范化依据、冲突/待确认原因和处理操作。原文页签只读，证据片段带统一编号和位置。能力编辑必须先展示影响预览，点击“保存为草稿”后才落库；已确认版本只能查看，不能原地修改。

### 4.6 冲突、确认与完成

冲突处理提供“合并”“分开”“重命名后合并”。存在阻塞冲突时，“确认并冻结”不可执行。确认成功后显示冻结版本、确认时间、可信等级、导出按钮和“进入阶段二”入口；进入阶段二只导航，不自动开始面试。

## 5. 状态与反馈映射

| 业务状态 | 前端表现 | 允许动作 |
|---|---|---|
| `COLLECTING` | 可添加材料、查看历史 | 添加、删除/移出、开始分析 |
| `ANALYZING` | 步骤进度、处理中标签 | 查看进度、取消/等待、失败恢复 |
| `REVIEWING` | 总模型、单 JD、待确认徽标 | 查看证据、编辑草稿、处理冲突、聚合 |
| `CONFIRMED` | 冻结版本和完成状态 | 查看、导出、进入阶段二、创建新草稿 |
| `ARCHIVED` | 归档标签 | 查看、恢复、删除 |

所有工作台操作都生成 `OperationCard`；操作卡片必须与后端事件结果一致，并提供影响查看或撤销入口（适用时）。

## 6. 功能—组件—接口—验收映射

| 功能需求 | 前端组件 | 主要接口 | 验收要点 |
|---|---|---|---|
| 创建/历史任务 | `HistoryNav` | `POST/GET /api/projects` | 当前任务高亮，按更新时间排序 |
| 四种 JD 入口 | `MaterialDialog` | `/jds/text`、`/jds/file`、`/jds/link` | 来源可追踪，提交后有事件卡片 |
| 解析与失败恢复 | `StageWorkbench`、`ParseFailure` | `/analysis/run`、`/analysis`、`/jds/{id}/retry`、`/failure` | 步骤明确，失败隔离，重试不重复 |
| 单份模型与证据 | `JdPicker`、`SingleJdModel`、`EvidenceView` | `GET /api/projects/{id}/analysis` | 每项能力可回到原文证据 |
| 总模型与聚合 | `TotalModel` | `/aggregate`、`GET /api/models/{id}` | 权重合计 100%，资历/约束分离 |
| 冲突处理 | `ConflictDecision` | `/conflicts/{id}/resolve` | 阻塞冲突解决前不可确认 |
| 能力编辑 | `CompetencyEditor` | `PATCH /api/competencies/{id}` | 草稿可改，显示影响预览，确认版不可改 |
| 移出/重新加入 | `JdPicker`、`ReaddJd` | `PATCH /api/jds/{id}`、`POST /readd` | 移出不删除，重新加入可复算 |
| 确认/导出 | `FinalReview`、`CompletedStage` | `/api/models/{id}/confirm`、`/export` | 生成不可变快照并可下载 |
| 对话/工作台一致 | `ConversationTimeline`、`OperationCard` | `/events` | 每次操作可审计、刷新后状态保持 |

## 7. 原型对应关系

`.superpowers/brainstorm` 中的阶段一原型作为交互参考，不直接逐页复制到生产代码。最终实现收敛到上述组件：添加材料（`stage1-document-picker*`）、解析状态/失败（`stage1-parsing-progress*`、`stage1-parse-failure*`）、单 JD/总模型（`stage1-single-jd-model*`、`stage1-total-model`）、证据与详情（`stage1-item-detail*`、`stage1-jd-source-trace*`）、冲突与确认（`stage1-conflict-*`、`stage1-final-review*`、`stage1-complete*`）。带 `v2/v3` 的文件视为迭代稿，开发以本设计和实施计划为准。

## 8. 阶段一前端验收

- 桌面端保持“历史导航 + 对话 + 右侧工作台”三栏，窄屏工作台从右侧滑出。
- 一级分页始终只有“总模型”和“单份 JD 模型”。
- 添加、解析、失败、冲突、编辑、确认、导出均有明确状态和可恢复动作。
- 正式能力项均能打开证据详情；原文保持只读。
- 总模型能力权重合计 100%，经验、证书和约束不进入能力权重。
- 已确认版本不可编辑；进入阶段二不会自动启动面试。
- 工作台操作与对话操作卡片、后端事件保持一致。
- 键盘焦点、状态文字、对比度、触控尺寸和减少动效遵循全局基线。
