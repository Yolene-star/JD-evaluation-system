# 阶段三：人才画像报告 UI 设计规格

## 1. 设计目标

第三阶段 UI 采用“报告概览优先”的信息架构。用户打开报告后应依次理解：整体结果、结果完整性、各能力表现、评分依据、优势与短板、发展建议以及报告所使用的数据和规则版本。

界面必须强调结果的可解释性，避免把实验性评分包装成权威测量或招聘结论。`PARTIAL` 报告必须持续显示评价覆盖范围；未完成能力项不得显示为 0 分。

## 2. 响应式总体布局

### 2.1 桌面端：顶部指标加双栏主体

`>= 1200px` 使用桌面方案 A：

```text
顶部：报告标题、版本选择器、更多菜单
锚点导航：概览 / 能力评价 / 优势短板 / 发展建议 / 版本信息
结果提示：FULL 或 PARTIAL 及覆盖范围
指标区：岗位匹配度 / 已评价能力项 / 评价覆盖度
双栏区：综合评价 / 雷达图
内容区：优势、短板、建议
详细区：能力评价矩阵
底部：版本摘要和重新计算入口
```

`768px–1199px` 保持同样的信息顺序，但允许双栏变为上下排列，缩小雷达图，不产生核心内容横向滚动。

### 2.2 移动端：纵向报告卡片

`< 768px` 使用移动方案 C：

```text
岗位和报告版本
FULL/PARTIAL 提示
岗位匹配度卡片
已评价能力项和覆盖度
综合评价卡片
能力条形列表
优势卡片
短板卡片
发展建议卡片
版本信息与操作入口
```

移动端不压缩桌面表格和双栏，而是重新组织为纵向卡片。雷达图可保留，但不作为首屏第一元素，且必须有能力列表作为替代内容。

## 3. 顶部导航与版本操作

桌面端顶部：

```text
← 返回测评    后端工程师 · 人才画像报告       [报告 v3 ▾] [更多 ⋯]
```

版本选择器显示当前和历史报告版本。更多菜单包含：

- 重新计算；
- 重试叙述生成；
- 查看评分规则；
- 查看生成输入版本。

“查看评分规则”必须能看到当前报告使用的评分规则版本，以及能力达成度公式、部分结果权重归一化策略和未完成能力项处理策略。可由报告详情一并返回，也可通过评分规则接口读取。

移动端顶部只保留返回、标题和更多按钮，岗位与版本显示在副标题中。版本选择和更多菜单使用底部弹层。

报告采用单页滚动和顶部锚点导航：

```text
[概览] [能力评价] [优势短板] [发展建议] [版本信息]
```

桌面端锚点可吸顶；移动端允许横向滚动或收纳进“跳转到”菜单。滚动定位后标题不能被吸顶区域遮挡。

## 4. 概览区

概览区分为三个信息层级：结果可信度和整体指标、综合解释和能力分布、进入详细评价的入口。

```text
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ 岗位匹配度        │ │ 已评价能力项      │ │ 评价覆盖度        │
│ 71.4%            │ │ 4 / 6            │ │ 70%              │
│ 部分结果          │ │                  │ │ ███████░░░        │
└──────────────────┘ └──────────────────┘ └──────────────────┘

┌──────────────────────────────────────┐ ┌──────────────────────────────┐
│ 综合评价                             │ │ 能力分布                     │
│ 候选人具备较扎实的后端开发基础……     │ │ 雷达图或能力概览             │
│ [查看评分依据]                        │ │ 部分结果的未评价项说明        │
└──────────────────────────────────────┘ └──────────────────────────────┘
```

岗位匹配度使用大号纯数字和小型辅助信息，不使用大型环形仪表盘。覆盖度使用带文字数值的短进度条。`PARTIAL` 报告显示温和但明确的提示条：

```text
ⓘ 本报告为部分结果：已评价 70% 权重，系统设计尚未完成评价。
```

移动端顺序为：结果提示、匹配度、能力项数量和覆盖度、综合评价、能力分布。

## 5. 能力评价矩阵

桌面端使用表格：

```text
能力项 | 分数 | 达成度 | Rubric 档位 | 置信度 | 证据摘要 | 操作
```

默认顺序沿用阶段一胜任力模型中的稳定顺序。只提供“全部 / 已评价 / 未完成”状态筛选，不提供分数排序，避免弱化岗位模型的原有结构。

展示规则：

- 分数是主信息；
- 达成度使用短进度条并显示文本数值；
- Rubric 档位使用文字标签；
- 置信度显示“高 / 中 / 低”，不只依赖颜色；
- 证据摘要显示正向、负向、缺失和不确定证据数量；
- `INCOMPLETE` 显示“不可完全评价”，不显示空分数进度条或 0 分。

“已评价能力项”统计口径为 `status == SCORED` 的能力项数量。`EXHAUSTED` 能力项若已形成可评分结果，计入已评价数量，但在能力详情中保留“达到追问上限”或证据不足说明；`INCOMPLETE` 不计入。

移动端将每一行转换为能力卡片：

```text
┌────────────────────────────────────────┐
│ Java                         已评价  › │
│ 8 / 10          达成度 80%              │
│ ████████░░      Rubric 7–8              │
│ 高置信度 · 4 条证据                     │
└────────────────────────────────────────┘
```

## 6. 证据抽屉

桌面端点击能力项或“查看证据”后从右侧打开抽屉；移动端使用底部或接近全屏的抽屉。抽屉不离开报告页面，并包含：

1. 能力名称、分数、达成度和 Rubric 档位；
2. 评分解释；
3. Rubric 指标完成情况；
4. 正向、负向、缺失和不确定证据；
5. 原始回答片段和回答轮次；
6. Rubric 与评分规则版本；
7. 查看完整原始回答的入口。

证据类型使用“文字标签 + 图标 + 局部颜色”：

- 正向：绿色、勾选图标和“正向证据”；
- 负向：深红色、警示图标和“负向证据”；
- 缺失：琥珀色、缺口图标和“缺失证据”；
- 不确定：灰蓝色、问号图标和“不确定证据”。

任何含义均不得只依靠颜色表达。

## 7. 优势、短板与发展建议

桌面端使用三列卡片，移动端改为纵向卡片。三类内容使用不同语义层级：

- 核心优势：正向、稳定，使用低饱和青绿点缀；
- 能力短板：需要关注但不制造失败感，使用局部琥珀色；
- 发展建议：行动导向，使用编号和主强调色入口。

每条内容必须显示关联能力，并提供证据入口。区域顶部或底部使用轻量说明：

```text
人才画像叙述 · 基于本报告评分与证据生成
```

`PARTIAL` 报告不得对未完成能力项作确定性判断，只能建议继续完成测评以获得完整评价。

## 8. 图表规则

- 雷达图用于快速比较，能力矩阵用于准确读取，证据抽屉用于解释原因；
- 雷达图只绘制 `SCORED` 能力项；
- `INCOMPLETE` 不绘制为 0 分，使用未评价说明或留空；
- `PARTIAL` 图表标题必须标明“部分结果”；
- 同时提供表格或能力列表，不能只依赖图表；
- 图表加载失败时回退到能力评价表，并提供重试入口。

## 9. 版本信息与重新计算

页面底部显示用户可读的版本摘要：报告版本、生成时间、完成类型、证据包版本、岗位模型版本、Rubric 版本和评分规则版本。

“查看生成输入”打开抽屉，展示已评价/未评价能力项以及匹配度计算方式。“重新计算”必须使用确认框，明确：

```text
当前报告 v3 不会被覆盖，系统将创建报告 v4。
```

AI 叙述重试不改变基础评分快照，失败时显示“基础评分和证据仍然可用”。

报告概览还需轻量展示两个相互独立的状态：`评分报告：可用` 与 `人才画像叙述：生成中 / 可重试 / 已完成`。雷达图、能力矩阵、匹配度和人才画像叙述引用同一份不可变报告快照；叙述状态变化不得改变图表和评分数值。

## 10. 空状态与异常状态

统一采用“说明原因 + 保留可用内容 + 提供下一步动作”的模式，覆盖：

- 尚未生成报告：说明证据已准备好并提供“生成报告”；
- AI 叙述失败：继续展示基础评分并提供重试；
- Rubric 缺失或版本冲突：阻止生成并提供缺失项/版本入口；
- 全部能力未完成：匹配度显示 `—`，引导返回测评；
- 图表失败：继续展示能力表格并允许重试；
- 报告生成中：显示具体阶段，不使用无意义的无限旋转。

## 11. 视觉系统

沿用全局温和、专业、低饱和方向：暖白背景、近白面板、深青灰主文字、中性灰辅助文字、低饱和青绿强调色。高分使用深绿色，中等分数使用青绿或蓝绿色，低分使用琥珀色，未完成使用灰蓝色，错误使用局部深红色。

分数以深色文字为主，进度条使用低饱和色。避免大面积红黄绿填充、装饰性渐变和权威仪表盘视觉。

## 12. 无障碍与交互约束

- 抽屉、弹层支持 Escape 关闭、焦点陷阱和关闭后的焦点回归；
- 抽屉打开时锁定背景滚动，并保留报告滚动位置；
- 键盘可完成版本切换、证据查看、重试和重新计算；
- 移动端触控目标至少 `44×44px`；
- 进度条和图表提供文本数值或表格替代；
- 状态使用文字、图标和结构表达，不只依赖颜色；
- `prefers-reduced-motion: reduce` 下取消非必要动画；
- 错误信息靠近触发位置，并提供明确恢复动作；
- 正文基准字号不小于 `16px`，长文本保持适宜行宽和行高。

## 13. UI 验收标准

- 首屏能看出岗位、报告版本、完整/部分结果、匹配度和评价覆盖度；
- 用户能从任何能力项进入评分依据并定位原始回答；
- 未完成能力项在数字、图表、表格和叙述中均不会显示为 0 分或确定性短板；
- 桌面端使用概览双栏和能力矩阵，移动端使用纵向卡片且无核心横向滚动；
- 历史报告可切换，重新计算不会覆盖当前报告；
- AI 叙述失败时，基础评分、匹配度、证据和图表仍可使用；
- 在 `375px`、`768px`、`1024px` 和 `1440px` 宽度下内容可读，操作不被遮挡；
- 雷达图、能力矩阵和证据抽屉中的分数与状态保持一致。
