# 阶段二前端 UI 设计：专注对话型自适应测评

> 文档状态：已确认的前端设计
> 适用阶段：阶段二——结构化自适应测评与动态追问
> 关联文档：[阶段二功能设计](2026-09-09-stage2-adaptive-assessment-design.md)、[阶段二实施计划](../plans/2026-09-09-stage2-adaptive-assessment-implementation.md)、[全局交互基线](../../../design/00-全局交互基线设计.md)

## 1. 设计目标

阶段二前端沿用阶段一已经确认的 AppShell 和三栏页面骨架，但把视觉注意力放在中间对话区。用户始终能看到当前问题、自己的回答、系统的分析状态和下一步动作；右侧工作台保留完整结构化信息，但以较低视觉权重辅助理解进度、能力状态和证据摘要。

本设计同时支持两种问题形态：

- **单项题**：只观察一个能力项，直接显示该能力标签、证据摘要和定向追问。
- **综合题**：一道问题覆盖多个相关能力项，显示“综合题 · 覆盖 N 项能力”和多个能力标签；同一回答的证据按能力项分组，只有证据不足的能力项触发追问。

两种形态使用同一页面骨架、输入位置、工作台位置和状态反馈组件，不拆成两套页面。

## 2. 页面信息架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部栏：项目 / 阶段轨道 / 模型版本 / 测评状态                 │
├──────────┬──────────────────────────────────┬────────────────┤
│ 历史导航 │ 专注对话区                         │ 测评工作台      │
│          │ 页面标题与说明                     │ 会话状态        │
│          │ 问题卡片                           │ 进度            │
│          │ 用户回答                           │ 能力项状态      │
│          │ 分析/证据卡                         │ 证据摘要        │
│          │ 定向追问                           │ 暂停/继续/结束  │
│          │ 回答输入区                         │                │
└──────────┴──────────────────────────────────┴────────────────┘
```

### 2.1 视觉优先级

1. 当前问题和用户回答输入区。
2. AI 分析结果、追问和错误恢复动作。
3. 当前能力项、追问次数和整体进度。
4. 其他能力项列表、证据摘要和模型版本等辅助信息。

右侧工作台不能删除功能设计中要求的状态和证据字段，只通过字号、间距、折叠和色彩层级降低干扰。证据详情默认折叠，用户主动查看时通过 `EvidenceDrawer` 打开。

## 3. 组件设计与职责

### 3.1 页面级组件

| 组件 | 职责 | 不负责 |
|---|---|---|
| `AssessmentPage` | 读取服务端会话快照并组合页面 | 不本地推断状态转换 |
| `AssessmentWorkbench` | 显示会话状态、进度、能力列表、证据摘要和操作 | 不计算能力完成度 |
| `ConversationTimeline` | 按时间顺序渲染问题、回答、分析、追问和错误卡 | 不调用 AI |
| `EvidenceDrawer` | 查看回答原文、证据类型、来源轮次和能力归属 | 不修改证据 |

### 3.2 对话组件

| 组件 | 关键输入 | 展示规则 |
|---|---|---|
| `AssessmentIntroCard` | 会话状态、能力项总数、规则摘要 | `READY` 时显示；说明覆盖范围、每项最多 2 次追问和数据用途 |
| `QuestionBubble` | `content`、`turnType`、`coveredCompetencies`、`followUpTarget` | 单项题显示 1 个标签；综合题显示综合题标签和 1–3 个能力标签 |
| `AnswerComposer` | `status`、`draft`、`onSubmit` | 多行输入；提交中禁用按钮；服务端确认前保留草稿 |
| `ThinkingIndicator` | `phase` | 显示“正在分析回答/正在生成追问”等具体阶段 |
| `EvidenceInlineCard` | 按能力分组的 observations、充分度、追问原因 | 单项题直接显示摘要；综合题展开后按能力项分组 |
| `RetryNotice` | 错误类型、是否保留回答、`onRetry` | 靠近对应回答显示重试和保留回答继续选项 |
| `AssessmentCompletionCard` | `FULL/PARTIAL`、完成项、未完成项 | 明确结果类型，并提供证据包入口；不显示正式评分 |

### 3.3 工作台组件

工作台顺序固定为：会话状态栏 → 进度区 → 能力项状态 → 证据摘要 → 操作区。

- **会话状态栏**：岗位名称、模型版本、`READY/IN_PROGRESS/PAUSED/COMPLETED/PARTIALLY_FINISHED/FAILED` 状态徽标。
- **进度区**：显示 `已完成能力项 / 总能力项` 和线性进度条。综合题覆盖但尚未进入终态的能力项不能计入已完成数量。
- **能力项状态**：显示名称、状态、主问题/追问数量和证据充分度。当前能力项使用高亮边框加“当前/本题观察/追问中”文字，不只使用颜色。
- **证据摘要**：显示正向、负向、不确定、待补充数量；点击进入证据抽屉。
- **操作区**：暂停、继续、结束测评、查看证据包。结束测评必须经过确认框，并说明未完成项数量和 `PARTIAL` 含义。

## 4. 状态到 UI 的映射

| 服务端状态 | 对话区 | 工作台 | 可用操作 |
|---|---|---|---|
| `READY` | 显示介绍卡和开始按钮 | 显示总能力项与模型版本 | 开始 |
| `IN_PROGRESS` + `ASKING` | 显示主问题和回答输入 | 当前项“测评中” | 提交、暂停、结束 |
| `IN_PROGRESS` + `FOLLOW_UP` | 显示定向追问和追问次数 | 目标项“追问中”，已充分项保持完成 | 提交、暂停、结束 |
| AI 分析中 | 显示具体分析阶段 | 状态栏显示处理中，不改变能力终态 | 等待；禁止重复提交 |
| 可重试失败 | 保留用户回答，显示 `RetryNotice` | 当前项保持原状态，显示可重试 | 重试、结束 |
| `PAUSED` | 显示暂停说明，输入区只读 | 显示恢复按钮 | 恢复、结束 |
| `COMPLETED` | 显示 `FULL` 完成卡 | 所有能力项为终态 | 查看证据包 |
| `PARTIALLY_FINISHED` | 显示 `PARTIAL` 完成卡和未完成项 | 未完成项标记 `INCOMPLETE` | 查看证据包、创建新会话 |
| `FAILED` | 显示会话级失败原因 | 显示创建新会话 | 创建新会话 |

## 5. 单项题与综合题

### 5.1 单项题

单项题的 `coveredCompetencies.length === 1`：

- 问题卡只显示一个能力标签，如“系统设计”；
- 不显示“综合题 · 覆盖 N 项能力”；
- 证据卡直接显示该能力的正向、负向、缺失和不确定证据；
- 定向追问使用“补充〈能力项〉证据”的文案；
- 右侧只高亮当前能力项，其他能力项保持“未开始”或“已完成”。

### 5.2 综合题

综合题的 `coveredCompetencies.length` 为 2–3：

- 问题卡显示“综合题 · 覆盖 N 项能力”和能力标签；
- 用户回答只保存一份完整原文；
- 分析卡按 `competency_id` 分组显示证据和充分度；
- 已充分能力项显示“证据充分”，不再被重复追问；
- 证据不足能力项显示“追问中”和该项的 `1 / 2` 或 `2 / 2`；
- 总进度只统计进入 `SUFFICIENT` 或 `EXHAUSTED` 的能力项。

典型展示：

```text
综合题回答
  系统设计  → 证据充分
  问题分析  → 追问中（只追问问题分析）
  沟通表达  → 证据充分
```

## 6. 前端数据契约

前端以服务端返回的会话快照为唯一状态源。每次 mutation 完成后，用响应整体替换本地快照，不在组件内自行累加进度或切换能力项。

```ts
type AssessmentQuestion = {
  id: string;
  content: string;
  turnType: 'MAIN_QUESTION' | 'FOLLOW_UP';
  coveredCompetencyIds: string[];
  followUpTargetCompetencyId?: string;
};

type CompetencyProgress = {
  competencyId: string;
  name: string;
  status: 'PENDING' | 'ASKING' | 'FOLLOW_UP' | 'SUFFICIENT' | 'EXHAUSTED' | 'INCOMPLETE';
  followUpCount: number;
  evidenceSufficiency: 'SUFFICIENT' | 'INSUFFICIENT' | 'UNCERTAIN';
};

type AssessmentSnapshot = {
  sessionId: string;
  status: 'READY' | 'IN_PROGRESS' | 'PAUSED' | 'COMPLETED' | 'PARTIALLY_FINISHED' | 'FAILED';
  completion: 'NONE' | 'FULL' | 'PARTIAL';
  modelVersionId: string;
  currentQuestion?: AssessmentQuestion;
  competencies: CompetencyProgress[];
  turns: AssessmentTurn[];
  retryable: boolean;
};
```

组件接口约束：

- `AnswerComposer` 只发出 `{ content, idempotencyKey }`；
- `QuestionBubble` 只根据 `coveredCompetencyIds` 渲染单项或综合题，不改变状态；
- `EvidenceInlineCard` 接收按能力项分组的数据，不从文本猜测归属；
- `AssessmentWorkbench` 接收服务端进度，不在前端重新计算完成数量。

## 7. 响应式与可访问性

- `>= 1440px`：折叠导航 + 宽对话区 + 右侧常驻工作台。
- `1024px–1439px`：三栏保留，左导航收窄，工作台保持可读最小宽度。
- `768px–1023px`：工作台改为右侧抽屉，底部提供“对话/工作台”入口。
- `< 768px`：单栏对话，工作台接近全屏从右侧滑入；打开时锁定背景滚动，关闭后返回触发按钮焦点。

必须满足：

- 正文基准字号不小于 `16px`，普通文本对比度至少 `4.5:1`；
- 触控目标至少 `44×44px`；
- 所有图标按钮有可访问名称，不能用 emoji 代替功能图标；
- 键盘可以完成开始、提交、暂停、恢复、打开证据抽屉和结束确认；
- 抽屉/确认框有焦点陷阱、Escape 关闭和焦点回归；
- 状态不能只靠颜色表达，同时使用文字或图标；
- `aria-live="polite"` 宣布分析、追问生成、错误和完成状态；
- `prefers-reduced-motion: reduce` 下取消非必要位移动效；
- 核心内容不使用横向滚动。

## 8. 交互与动效

只使用表达状态连续性的轻量动效：问题进入、回答提交确认、证据卡展开和工作台抽屉打开，常规过渡 `150–250ms`。分析中状态显示具体阶段文字，不使用无意义的无限旋转。错误出现时不清空回答，不把用户带离当前能力项。

## 9. 前端测试矩阵

### 9.1 组件测试

- 单项题显示一个能力标签且不显示综合题标签；
- 综合题显示覆盖数量、多个能力标签和按能力分组的证据；
- 综合题中只有证据不足能力项显示定向追问；
- 提交中按钮禁用且回答草稿保留；
- AI 分析、超时、重试、暂停、完成和部分完成状态均有明确文案；
- 工作台进度来自服务端快照，不因前端重复渲染而递增。

### 9.2 浏览器测试

- 桌面三栏布局与阶段一 AppShell 一致；
- 375px、768px、1024px、1440px 宽度无核心内容横向溢出；
- 移动端工作台抽屉打开/关闭后焦点和滚动位置正确；
- 键盘完成整条测评主路径；
- 刷新后恢复当前问题、回答历史、能力状态和追问次数。
